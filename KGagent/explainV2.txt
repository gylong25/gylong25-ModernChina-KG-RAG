中国近代史人物关系图谱 - 第二版变更说明

1. 主要变更概述

本版本在第一版的基础上，重点完善了 GraphRAG 问答系统的能力，引入了混合检索（图谱检索 + 向量检索），增强了实体识别和路径查找，并提供了完整的评估框架。核心目标是提升问答准确性和系统可观测性。


2. 详细变更列表

2.1 功能新增

- 新增向量检索模块（src/vector_store.py）：
  - 集成 ChromaDB 持久化向量数据库
  - 实现轻量级 Hash 嵌入函数，无需依赖 torch/sentence-transformers，降低部署难度
  - 支持从 JSON 数据重建向量索引
  - 提供语义搜索能力，支持 Top-K 召回
  - 变更位置：新增文件 src/vector_store.py
  - 变更原因：弥补纯结构化图谱检索在模糊查询上的不足

- 新增评估框架（evaluate_graphrag.py）：
  - 支持批量测试用例执行
  - 使用 Qwen 模型作为自动评估器，判断答案正确性
  - 生成详细的评估报告（JSON 格式），包含准确率、得分、原因等
  - 支持命令行参数配置（输入文件、输出文件、样本限制、评估模型）
  - 变更位置：新增文件 evaluate_graphrag.py
  - 变更原因：建立客观评估标准，便于迭代优化

- 新增配置管理（.env, .env.example, src/config.py 增强）：
  - 使用 python-dotenv 管理环境变量
  - 新增 ChromaDB 相关配置项
  - 新增向量检索 Top-K、图谱路径最大深度等配置
  - 变更位置：新增文件 .env, .env.example；修改 src/config.py
  - 变更原因：提升配置灵活性，便于多环境部署

- 新增测试用例文件：
  - test.json：基础测试用例
  - test1.json：增强版测试用例（更难）
  - 变更位置：新增文件 test.json, test1.json
  - 变更原因：为评估框架提供测试数据

- 新增评估结果文件：
  - eval_result0.json, eval_result_test1.json
  - 变更位置：新增结果文件
  - 变更原因：记录评估结果，便于对比分析

2.2 功能优化

- GraphRAG 服务增强（src/graphrag.py）：
  - 引入混合检索策略（图谱检索 + 向量检索）
  - 增强实体提取能力，使用图谱驱动的实体识别
  - 优化路径检索，优先寻找多跳路径并优先使用已定义关系
  - 向量存储采用延迟初始化，UI 加载不受向量初始化失败影响
  - 优化上下文构建逻辑，支持更丰富的上下文组合
  - 变更位置：修改 src/graphrag.py
  - 变更原因：提升问答质量，减少幻觉

- 图谱存储层优化（src/graph_store.py）：
  - 新增 find_person_entities_in_question()：从问题中提取实体，支持别名匹配
  - 新增 get_prioritized_neighborhood()：优先返回已知类型关系，限制未知关系数量
  - 新增 find_path_between_entities()：支持偏好已知关系的路径查找
  - 新增 _find_path_between_entities()：内部路径查找实现
  - 优化 get_graph_context()：兼容新的检索策略
  - 新增 _format_context_row()：格式化关系行
  - 变更位置：修改 src/graph_store.py
  - 变更原因：提升检索精度和效率

- 配置文件增强（requirements.txt）：
  - 新增 chromadb>=0.5.5：向量数据库依赖
  - 新增 python-dotenv>=1.0.1：环境变量管理
  - 新增 pandas>=2.2.2：数据处理依赖
  - 变更位置：修改 requirements.txt
  - 变更原因：支持新增功能

- ETL 模块优化（src/etl.py）：
  - 增强编码容错能力（支持 utf-8, utf-8-sig, gb18030）
  - 优化关系类型转换逻辑，支持中文关系标签的安全编码
  - 变更位置：修改 src/etl.py
  - 变更原因：提升数据导入的鲁棒性

2.3 问题修复

- 无明确记录的问题修复（通过代码重构间接提升系统稳定性）

2.4 架构调整

- 引入分层设计：配置层 → 存储层（图谱/向量） → 服务层 → UI 层
- GraphRAG 服务从单纯依赖图谱检索扩展为混合检索架构
- 评估框架独立于主应用，支持离线评估
- 变更位置：整体架构
- 变更原因：提升代码可维护性和扩展性

2.5 代码重构

- 配置管理从硬编码改为环境变量驱动
- 向量检索独立为模块，便于替换不同的嵌入后端
- 图谱存储接口更加聚焦，每个方法职责单一
- 变更位置：多个文件
- 变更原因：提升代码质量和可测试性

2.6 依赖更新

- 新增：chromadb>=0.5.5
- 新增：python-dotenv>=1.0.1
- 新增：pandas>=2.2.2
- 变更位置：requirements.txt
- 变更原因：支持新增功能


3. 兼容性说明

3.1 向后兼容性

- Neo4j 数据结构完全兼容第一版，无需重新导入数据
- Streamlit UI 保持一致的用户体验
- API 接口保持向后兼容

3.2 迁移注意事项

- 需要安装新增的依赖包：pip install -r requirements.txt
- 需要配置 .env 文件（可从 .env.example 复制）
- 首次运行会自动构建 ChromaDB 向量索引
- 评估功能是可选的，不影响主应用运行


4. 已知问题

- 向量检索使用轻量级 Hash 嵌入，语义理解能力有限，建议后续可替换为专业中文嵌入模型
- 评估器依赖 Qwen 模型，评估结果受模型表现影响，可能存在不一致
- 暂无多轮对话记忆功能，无法处理上下文依赖的连续提问
- ChromaDB 索引在 Windows 上首次构建可能较慢，建议使用性能较好的机器
