中国近代史人物关系图谱 - 初始版本说明

从http://openkg.cn/获取了近代史人物的结构化数据，基于该数据构建了Neo4j知识图谱。
当前项目已经完成了一个可运行的知识图谱原型，核心目标是将 JSON 人物数据导入 Neo4j，并在 Streamlit 页面中完成图谱检索、可视化和基于图谱的问答。

已实现功能

1. 数据转换与入库
- 读取 `data-json.json` 中的近代史人物列表。
- 以 `中文名` 作为人物节点主键。
- 将 `附加名称` 合并到 `aliases` 属性中，支持别名检索。
- 自动解析 `毕业于`、`作品`、`相关人物` 等字段并生成图谱关系。
- 对 `相关人物` 中的 `未知` 关系统一标记为 `UNTYPED_RELATION`。
- 使用 Neo4j `MERGE` 语句避免节点重复写入。
- 为人物、组织、作品建立唯一约束。

2. 图谱可视化
- 使用 Streamlit 作为前端页面框架。
- 提供人物搜索框，支持按姓名或别名查询。
- 查询人物及其多度邻域关系，并生成交互式图谱。
- 使用 Pyvis 在页面中展示关系网络。
- 节点颜色已区分：
  - 人物：红色
  - 组织：蓝色
  - 作品：绿色

3. GraphRAG 问答
- 接入阿里百练 DashScope 的 Qwen 模型。
- 在回答问题前，先从 Neo4j 检索相关实体与关系上下文。
- 将图谱事实上下文与用户问题一起送入模型。
- 通过“先检索、后生成”的方式降低幻觉。
- 已兼容 OpenAI 格式调用方式，便于后续切换接口。

4. 统计分析
- 在侧边栏展示图谱基础统计信息：
  - 总人数
  - 总关系数
- 展示连接数最高的前 5 位核心人物。

5. 检索优化
- 支持双向关系查询，避免只从单方向检索导致漏召回。
- 对明确关系和 `UNTYPED_RELATION` 做了优先级区分。
- 支持两个实体之间的 2 层以内最短路径检索。
- 在上下文中清晰标注关系方向，方便模型理解。

项目结构

- `app.py`：Streamlit 主程序
- `etl_import.py`：数据入库脚本
- `src/config.py`：配置加载
- `src/etl.py`：JSON 解析与入库逻辑
- `src/graph_store.py`：Neo4j 查询封装
- `src/graphrag.py`：图谱检索与问答编排
- `src/visualization.py`：Pyvis 图谱渲染

运行前需要配置

- Neo4j 连接信息
- DashScope API Key
- DashScope OpenAI 兼容 Base URL
- 数据文件路径

当前版本定位

这是一个面向“展示 + 检索 + 问答”的初始版本，重点已经完成：
- 数据可导入
- 图可视化可展示
- 问答可基于图谱上下文生成
- 检索逻辑已做基础优化

后续可继续增强的方向包括：
- 更强的实体识别
- 更细粒度的关系类型规范化
- 多轮对话记忆
- 更完整的知识校验与数据清洗
- Docker 化部署
